# 라즈베리파이 감지 알림 연결

앱의 **더보기 → 주변 인식 연결**에서 서버 URL을 입력한다.
예: `ws://192.168.0.20:5000` (예시 주소이며 실제 라즈베리파이 IP/포트로 교체).
휴대폰과 서버는 같은 Wi-Fi 또는 서로 접근 가능한 네트워크에 있어야 한다.
주소는 기기에 저장된다. 실제 서버가 없어도 같은 화면의 테스트 버튼으로 네 가지 경고를 확인할 수 있다.

## 서버 계약

일반 TCP가 아닌 표준 WebSocket 서버를 사용한다. JSON 객체 하나를 WebSocket 텍스트 메시지 하나로 전송한다.
앱에서 서버로 제어 명령을 보내지는 않는다. 주변 인식 끄기는 앱 수신 연결과 경고 출력을 중단한다.

```json
{
  "event": "LEVEL1",
  "message": "전방 위험물 접근중! 즉시 정지하세요.",
  "ttc": 1.2,
  "timestamp": 1776859920.123
}
```

위 timestamp는 형식 예시다. 실제 송신 시에는 매번 Python `time.time()`을 넣는다.
`event`는 `LEVEL1`, `LEVEL2`, `CROSSWALK`, `GO` 중 하나이며, `message`는 비어 있지 않은 300자 이하 문자열이다.
`ttc`는 `LEVEL1`의 충돌 예상 초 또는 null이다. 나머지 이벤트는 null을 보낸다.
`timestamp`는 Unix **초 단위** 숫자다. 10초보다 오래됐거나 휴대폰보다 30초 이상 미래인 데이터는 무시한다.
양쪽 기기의 시간을 동기화하고, 재연결 시 지난 경고를 재전송하지 않는다.

## 알림 동작

| 이벤트 | 출력 |
| --- | --- |
| LEVEL1 | 긴 경고음, 연속 진동, 위험 문구와 TTC 배너 |
| LEVEL2 | 짧은 경고음 2회, 짧은 진동 2회, 문구 배너 |
| CROSSWALK | 짧은 경고음 2회, 짧은 진동 2회, 수신 문구 TTS |
| GO | 수신 문구 TTS, 진동 없음 |

우선순위: LEVEL1 > LEVEL2 > CROSSWALK > GO > 일반 앱 음성.
같은 경고를 연속 수신하면 배너 유지 시간을 연장하고, 3초 이내에는 소리를 다시 시작하지 않는다.
같은 이벤트의 중복/역순 timestamp는 무시한다. 높은 위험 경고가 진행 중이면 GO 등 낮은 우선순위 경고는 버리고 나중에 재생하지 않는다.
경고 종료 후 진행 중인 경로의 현재 안내를 다시 읽는다. 테스트 출력에는 [테스트] 표시가 붙는다.
화면 읽기 기능이 켜져 있으면 안내 텍스트는 접근성 알림으로 전달해 앱 TTS와 중복하지 않는다.
iOS 진동의 길이·세기는 시스템 동작에 따르며 실제 아이폰에서 확인해야 한다.

## 실행 범위와 검증

앱이 전면에 있을 때 동작한다. 앱 전환/화면 잠금 시 소켓과 경고 출력을 중단하고 복귀하면 다시 연결한다.
백그라운드 위험 알림이나 원격 보호자 푸시 전송은 이 연결에 포함되지 않는다.
연결 해제 시 1, 2, 4, 8, 최대 10초 간격으로 재접속한다. 연결 상태는 감지 성공이나 안전을 보장하는 표시가 아니다.
WebSocket `onopen`은 서버 연결만 뜻한다. 감지 데이터는 최근 수신 알림에서 별도로 확인한다.

테스트 실행: `node --test tests/hazard-alerts.test.cjs`

기기 확인 순서:
1. 더보기에서 연결 화면을 열고 서버 연결 없이 네 이벤트를 테스트한다.
2. 실제 서버 주소를 저장하고 연결됨 표시를 확인한다.
3. 서버에서 최신 timestamp의 LEVEL1을 0.5초 간격으로 보내 출력이 반복해서 끊기지 않는지 확인한다.
4. 길안내 음성 중 경고를 보내 우선 출력/안내 복귀를 확인한다.
5. 서버 종료 후 재접속, 주변 인식 끄기, 앱 전환 후 복귀를 확인한다.

`GO`는 파이썬 쪽에서 횡단보도·초록불·위험 조건을 확인한 결과만 전송해야 한다.
권장 문구는 '초록불이 감지되었습니다.'이며, 단순한 빨간불 미검출을 출발 승인으로 사용하지 않는다.
