# 감지 JSON 거부 원인 확인

이 문구는 오디오 재생 전에 수신 데이터가 거부되었음을 뜻한다. 기존 검사는 event/message/timestamp/ttc와 시간 범위를 확인하며 이번 진단 추가에서는 허용 기준을 바꾸지 않았다. 실제 수신 JSON을 아직 확인하지 못했으므로 서버 시계, 형식 또는 제어 프레임 중 무엇이 원인인지 확정하지 않았다.

연결 화면에 [수신 진단: 코드], 구체적인 이유, 수신 원문 최대 650자를 표시한다. 텍스트를 길게 눌러 복사할 수 있다. 콘솔에는 [SeeQ hazard reject]를 종류 변경 또는 5초 간격으로 기록한다. 원문을 숨긴 채 모든 실패를 하나의 문구로 표시하던 부분을 보완했다. 오디오 오류와 수신 오류가 동시에 있으면 모바일 화면에 둘 다 표시한다.

- missing-event / unsupported-event: 실제 받은 필드와 event 값을 확인해야 한다. LEVEL1, LEVEL2, CROSSWALK, GO 외의 값을 임의 매핑하지 않는다.
- invalid-json / not-object / invalid-message / invalid-ttc: 표시된 원문으로 전송 형식을 확인한다.
- invalid-timestamp: Unix 초 단위 숫자가 없거나 문자열 등의 형식이다.
- timestamp-milliseconds: 밀리초로 보이는 숫자가 전송되었다. 현재 프로토콜은 Python time.time() 초 단위다. 임의 변환하지 않았다.
- stale: 휴대폰 기준 10초보다 이전. 전송 지연 또는 두 기기 시각 차이를 확인한다.
- future: 휴대폰보다 30초 이상 미래. 두 기기의 자동 날짜/시간을 확인한다. Unix 초는 표준시 기준이므로 한국 시간 9시간을 더해 해결하면 안 된다.

정상 프레임이 다음에 오면 수신 오류를 지우고 기존 경고 처리 함수로 전달한다. 거부된 프레임으로 경고음을 강제 재생하거나 시간 검사를 제거하지 않았다.

```powershell
cd C:\SeeQ-App
npx expo start --go --clear
```

이전 서버는 Ctrl+C로 종료하고 Expo Go를 완전히 다시 연다. 다시 연결한 뒤 새로 표시되는 [수신 진단: ...]와 수신 원문을 확인한다. 여전히 예전의 '지원하지 않거나 오래된...' 한 문구만 나오면 새 코드가 적용되지 않았거나 다른 프로젝트의 QR로 실행 중일 수 있다.

경고 테스트 버튼도 별도로 확인한다. 실제 수신 JSON 오류와 관계없이 테스트 버튼은 로컬 경고 경로를 사용한다. 테스트까지 무음이면 오디오 오류 문구도 함께 확인해야 한다.

검증: 진단/수신 복구 테스트 5개 + 기존 네이티브 경고/프로토콜/버튼 음성 검사 포함 42개 통과, TypeScript 및 변경 파일 ESLint 통과. 실제 라즈베리파이의 원문 확인과 단말 재시험은 아직 필요하다. 웹 후속 경고음 작업은 현재 모바일 수신 문제 확인을 우선한다. 공개 배포하지 않았다.
